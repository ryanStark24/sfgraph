# Claim ledger: sfgraph 1.8.3

### C-1.8.3-001: a project folder's git settings can no longer start a fetch or run a command

**What**: the git fix from the 1.9.0 branch (claim C-1.9.0-017), applied to the 1.8.2 code with no other change. `safeGitEnv()` in `packages/core/src/analyze/wip-changed-files.ts` returns the environment for every git child (`GIT_ALLOW_PROTOCOL=none`, `GIT_NO_LAZY_FETCH=1`, `GIT_TERMINAL_PROMPT=0`); it is passed to both git calls there, to `execGit` in `packages/core/src/extractors/filesystem/change-times.ts` and to `gitRevision` in `packages/cli/src/commands/ingest.ts`. `safeGitConfig` also passes `-c safe.bareRepository=explicit`, and `gitRevision` now uses `safeGitConfig`.

**Check**: on this change, on Linux with git 2.43.0: `pnpm build` and `pnpm typecheck` clean on every package; `cd packages/core && npx vitest run src/analyze/__tests__/wip-git-hostile-config.test.ts src/extractors/filesystem/__tests__` gave 5 files, 62 tests passed (the new file has 8 tests; on the 1.9.0 branch 7 of them failed against the unfixed code, and that comparison was not repeated here); `cd packages/cli && npx vitest run` gave 17 files, 83 tests passed.

**Untested / limits**: not run on macOS or Windows. `GIT_NO_LAZY_FETCH` is honoured only by newer git; on older git `GIT_ALLOW_PROTOCOL=none` is the layer that stops the fetch, and that was run only on git 2.43.0 (Linux). `gitRevision` has no direct test. Package versions are not bumped in this change. The whole-repository test suite was not run.
