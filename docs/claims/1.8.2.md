### C-1.8.2-062 (S-1.8.2-001, F01): Guard decides on a primitive method it sends, SOAP operation read from parsed markup, boundary stated

**What**: An independent probe of the guarded raw jsforce Connection found three ways a write reached the transport, plus one limit. (1) A `method` that is not a primitive string (`new String("POST")`, `["POST"]`, `{toString: () => "POST"}`) was treated as GET by the guard but stringified to POST by the transport. The guard now copies the request once, refuses any method that is not a primitive non-empty string (absent still means GET), and passes the checked copy on, so a getter that answers differently on a second read cannot change what was checked. This applies to `conn.request` and to `conn._transport.httpRequest`. (2) A SOAP POST to `/services/Soap/m/<v>` whose body hid a write behind `<!-- <readMetadata> -->` or `<![CDATA[<readMetadata>]]>` passed. `soapOperation` is now a small scanner (no new dependency): comments, CDATA and processing instructions are skipped as non-elements, a DOCTYPE, malformed, unbalanced or unquoted-attribute markup returns null, quoted attribute values may contain `>`, the Body must be a child of the single root and have exactly one child element, and its local name (prefix ignored) must be in `SOAP_READ_OPERATIONS`. A non-string body (Buffer) is refused. (3) `Object.getPrototypeOf(conn._transport).httpRequest.call(conn._transport, {method: "POST", ...})` still reaches the wire. jsforce 3.10.15 has `Transport.prototype.httpRequest` use a module-level fetch with no per-instance HTTP function, so the guard cannot sit below that call without patching jsforce. This is stated as the boundary: the guard covers every request made through sfgraph's connection objects (`conn.request`, `conn._transport.httpRequest`, and everything jsforce builds on them, including SOAP). Code that calls jsforce's prototype or internals directly is outside it. No sfgraph code does that, and extractors only receive the read facade, which has no reference to the connection.

**How**: `packages/core/src/extractors/live-org/transport-guard.ts` (`snapshotRequest` line 67, `soapOperation` line 103, `assertReadOnlyRequest` line 201 returns the checked copy, `installTransportGuard` line 233 sends it); boundary text in the file header, `README.md` (privacy line), `docs/PRIVACY.md` (read-only section, Limits), `CHANGELOG.md` (1.8.2 read-only entry). The facade's `metadata.retrieve` with a key-injection argument is refused by the guard (the safe outcome; the probe listed it as a blocked read); a normal `retrieve` request still passes (existing test "Metadata retrieve().complete() sends retrieve and its status polls").

**Check**: `cd packages/core && npx vitest run src/extractors/live-org/__tests__/read-only-proxy.test.ts`. Expect 22 passed. New: "refuses a method that is not a primitive string", "decides on the method it sends: a getter that changes on second read cannot flip it", "refuses SOAP bodies that hide a write behind a comment, CDATA or processing instruction". They use a real jsforce Connection with the recording transport and failed (3 failed, 19 passed) with the previous `transport-guard.ts` restored. The existing read tests (query, describe, tooling query, listMetadata, readMetadata, describeMetadata, retrieve and status polls) still pass.

**Untested**: The prototype-level call above is not blocked and has no test asserting a refusal. The scanner is not a full XML parser: it was not fuzzed, and it may refuse some exotic but valid envelopes (DOCTYPE, unquoted or unusual attribute syntax); jsforce's own request bodies are accepted. A hostile org response cannot reach the guard, which looks only at outgoing requests. No Salesforce org was contacted.

SQLite `LIKE` folds ASCII case, the same fold as the NOCASE column. `%`, `_` and `\` in the user's text are escaped, so they match themselves. `search()` in api.ts:115 calls it; `listAllQnames` and `SEARCH_MAX_SCAN` are gone from the web package.

**Check**: `... -t "F13"`: finds `ApexClass:Search49999` (seeded in 50 batches of 1,000, about 0.5 s), finds it again with a lower-case needle, and the `%`/`_`/`\` cases return only the literal matches. Failed on the old code. Audit runner `audit-scale.mjs` no longer prints `SEARCH_SILENT_CAP`; its assertion `hits.length === 0` now throws (the result is an object, and the hit is found).

**Untested**: a substring `LIKE '%x%'` cannot use an index, so it scans each label table inside SQLite (no JS allocation, stops at the limit). Search time on 50,000 nodes was not benchmarked beyond the test finishing in well under a second; very large orgs were not tried. Non-ASCII case folding follows SQLite NOCASE/LIKE (ASCII only).

### C-1.8.2-045 (S-1.8.2-011, F13): search reports when it stopped
