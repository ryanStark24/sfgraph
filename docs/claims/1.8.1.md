### C-1.8.1-020 (S-1.8.1-003): project ingest takes `lastModifiedAt` from git

- Done: `FilesystemMetadataSource.iterIndexed` builds a `ChangeTimes` lookup once per run (`packages/core/src/extractors/filesystem/change-times.ts`, class `ChangeTimes`, `load`) and every member's `ref.lastModifiedAt` comes from it (`extractors/filesystem/index.ts`, `makeRef`, `times.lookup`; DataPacks in the `iterIndexed` load wrapper).
- How: the lookup runs a fixed handful of git calls through an injectable runner (`rev-parse`, one `log --name-only -z`, one `diff HEAD`, one `ls-files --others`), never one process per file; each has a 60 s timeout and a 128 MB output cap, and on either the partial output is used. A clean tracked file gets its last commit time (`%ct`); a file edited since HEAD or untracked gets its mtime (newest); not a git tree, git failing, or a file git does not know gets mtime. A bundle or object folder (the whole object folder: fields, record types, rules) takes its newest file. The git safety config is the one `wip-changed-files.ts` uses (`safeGitConfig`, now exported).
- Check: `pnpm --filter @ryanstark24/sfgraph-core exec vitest run src/extractors/filesystem/__tests__/change-times.test.ts` (5 tests). "buckets match back-dated commits" makes commits 2, 45 and 400 days old with GIT_AUTHOR_DATE/GIT_COMMITTER_DATE, sets every mtime to now, and expects hot, current, dead. "a file edited since HEAD..." expects an edited and an untracked file hot. "a bundle or object folder..." expects the object at 2 days (newest field). "outside git..." expects mtime (hot, and a 200-day-old file stale). "history is read in a few batched calls..." counts runner calls for 40 classes: at most 5, exactly one `log`.
- Untested: a repo large enough to hit the 60 s timeout (partial-output path); submodules; shallow clones (a file last changed before the shallow boundary reads as the boundary commit time).

### C-1.8.1-021 (S-1.8.1-003): the change time reaches the nodes, for project, org and delta ingest

- Done: `parseMember` (`packages/core/src/ingest/parse-member.ts`, `stampSourceChangeTime`) replaces the parse-time `lastModifiedAt` on every node a member produces with `ref.lastModifiedAt` when it is a valid date; parse time stays the fallback when the source gave none. Parse-pool workers, the serial path and delta's pre-parse all go through `parseMember`, so delta ingest follows the same rule.
- Org ingest: the extractors already set `ref.lastModifiedAt` from `LastModifiedDate` (Apex, LWC, Flow, OmniStudio, Vlocity, security, integration, generic metadata and sobject), so they now take effect. Members the extractor has no date for (custom settings, describe-built objects in `object.ts`, OmniStudio retrieve) still use ingest time.
- Check: the "buckets match" test above runs the full `liveIngest`; `freshness_report` reads the same `lastModifiedAt` through `analyze.freshnessScore`. Docs: `docs/TOOLS.md` under `freshness_report`.
- Untested: an org ingest against a live org (no live Salesforce calls); there is no dedicated test that an org `LastModifiedDate` lands on the node, only the shared `parseMember` path is exercised, by the project tests.
