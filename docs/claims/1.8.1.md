### C-1.8.1-010 (S-1.8.1-002): reached rows carry status, active and events

- Done: `findDependents` reached rows now include `status` (Flow/FlowVersion node attribute), `active` (WorkflowRule and approval-process node attribute) and `events` (ApexTrigger attribute) when the node stores them; absent otherwise.
- How: `statusFieldsOf` in `packages/core/src/analyze/dependents.ts` (line 59) is spread into each row in `reach` (line 331). Attribute names confirmed in the parsers: `status` in `parsers/flow/parser.ts` (Flow and FlowVersion), `active` in `parsers/rules/workflow.yml` and `approval-process.yml`, `events` in `parsers/apex/trigger.ts`.
- Check: `packages/core/src/analyze/__tests__/dependents-status.test.ts` "reads them from node attributes after storage; absent when not stored" (real SQLite store round trip). Run `npx vitest run packages/core/src/analyze/__tests__/dependents-status.test.ts`; expect pass.

### C-1.8.1-012 (S-1.8.1-002): `active_only` and `events` filters

- Done: `trace_upstream` accepts `active_only` (boolean, default false) and `events` (string or array, optional); wired in `packages/mcp-server/src/tools/trace_upstream.ts` (schema lines 32-37, filter near line 80) with `keepByStatus` (`_reach_list.ts` line 241). `active_only` drops Flow/FlowVersion rows whose status is not Active, other rows whose status is Draft/Obsolete/InvalidDraft/Inactive/Deleted (case-insensitive; Network `Live` and registration `Complete` stay; test: BotVersion `Inactive` dropped, Network `Live` kept) and members whose `active` is false; members without status info stay. `events` keeps ApexTrigger rows whose events include any wanted event (`update` matches before and after update; a full name like `before insert` matches exactly); other rows are unaffected, as are triggers with no stored events. Defaults give unchanged output.
- Check: same test file: "active_only + events:update keeps the active flow, active rule and after-update trigger", "events alone filters triggers only; array form and full event names match", "active_only alone drops Draft/Obsolete/inactive and keeps triggers (no status info)". Fixture: Acme_Order__c with Active/Draft/Obsolete flows, an active and an inactive workflow rule, a before-insert and an after-update trigger.
- Schema size: the two new params push `tools/list` over its 10,000/7,000 character budget (`t5-tool-list.test.ts`), so `active_only` is plain optional boolean, `events` takes a string or array (a string is wrapped by a preprocess; the schema shows an array) and the trace_upstream / trace_downstream descriptions were shortened (still say "not found" for an unknown qname, required by `audit-review-i3-descriptions.test.ts`). Behavior of both traces is otherwise unchanged.
- Fold fix (Codex P2 on #15): a dropped row now also drops its folded members (a Flow's FlowVersion) from `data.edges`/`data.nodes` and the diagram, and `foldRows` (`dependents.ts`) gives a row the `status`/`active` of a folded member when it has none. Tests: `packages/core/src/analyze/__tests__/dependents-flow-fold.test.ts` (real `FlowParser` output) and "folded FlowVersion edges (parser shape)" in `trace-upstream-status.test.ts`.
- Note: filters hide rows (and their edges in `data` and the diagram), not the traversal; rows reached only through a hidden row still list. The CLI does not expose `trace_upstream`, so nothing to wire there. Documented in `docs/TOOLS.md` (trace_upstream section). Other rule-backed members: only workflow rules and approval processes store `active` today; any node with a boolean `active` attribute is covered. Untested: real-parser ingest of the status fields end to end (attribute names checked by reading the parsers; the tests seed nodes directly).
