### C-1.8.1-001 Everyday project folders (S-1.8.1-001)

- Done: project ingest now reads roles, groups, queues, reports, report types, dashboards, quick actions, static resources, email templates, flow definitions, translations, custom permissions, global and standard value sets, connected apps, applications, remote site settings, auth providers, topics for objects, settings and path assistants.
- How it works: `EXTRA_SPECS` (packages/core/src/extractors/filesystem/index.ts, around lines 467-492) lists each folder with the suffix and the Metadata API type name the live generic path uses. `walkMetaFolders` (around line 587) yields one opaque member per `<Name>.<suffix>-meta.xml`; reports, dashboards and email templates recurse and are named `<Folder>/<Name>` (the Metadata API fullName). Members arrive as XML, so `parse-member.ts` routes them to a YAML rule when one exists (`Report`, `Dashboard`) and to the opaque parser with the generic reference scanner otherwise, as for org ingest. Category is OPAQUE, as in the live path.
- Check: `cd packages/core && npx vitest run src/extractors/filesystem/__tests__/project-folders.test.ts -t "everyday metadata folders"`. Expect the test "gives one node per file in every listed folder" to pass (23 folders, one node each).

### C-1.8.1-002 Suffix fallback for unknown folders (S-1.8.1-001)

- Done: any other `<folder>/**/*.<type>-meta.xml` under a metadata root becomes an opaque member typed from its suffix (`gadget` becomes `Gadget`; `SUFFIX_TYPE_OVERRIDES` fixes irregular names such as `app` to `CustomApplication`, `resource` to `StaticResource`, `translation` to `Translations`).
- How it works: `walkMetaFolders` runs for every folder under the root that `HANDLED_SEGMENTS` (LEAF, FOLDER and bundle specs plus `objects`) does not own, to depth 6, never entering `node_modules`, `.git` and the other skip folders. `CLAIMED_SUFFIXES` (`cls`, `trigger`, `page`, `component`, `js`, `cmp`, `object`, `field`, `recordType`, `validationRule`, `listView`, ...) are never turned into members, so nothing is counted twice. Non-metadata files (no `-meta.xml` tail) are ignored, and a listed flat folder such as `staticresources/` does not recurse into unzipped resource folders. Coverage needs no change: the opaque nodes show in `unknownTypes` when they have no rule and no generic edges.
- Overlap guard: the fallback skips any folder that is or contains another discovered metadata root (so `force-app/main` is not walked as an unknown folder when `force-app/classes` and `force-app/main/default` are both roots), and `walkPackage` drops any member whose source path was already yielded. Test: `-t "yields a file once"`.
- Check: `npx vitest run src/extractors/filesystem/__tests__/project-folders.test.ts -t "falls back"` and `-t "never double-counts"`; then `npx vitest run src/ingest/__tests__/project-folders-ingest.test.ts -t "unknown folder"` (a report has `REPORTS_ON` and `READS_FIELD` edges, `Gadget` is in `coverage.unknownTypes`, `Report` is not).
- Judgement: the type map is a hand-written override list, not an existing registry (sfgraph has none for suffixes). An unlisted suffix is only capitalised, so a type whose name differs from its suffix and is missing from the list gets a wrong-cased type name (untested for types outside the list).

### C-1.8.1-003 Other subroots are searched (S-1.8.1-001, S-1.8.1-007)

- Done: `walkPackage` (packages/core/src/extractors/filesystem/index.ts, around lines 640-705) used to descend only `main` and `default`, so a project with `force-app/main/default` plus a sibling subroot (`force-app/extras/default`) lost the sibling. It now searches every sub-folder (depth 6) of a folder that holds no metadata folder, and treats a `default` folder as a root even if it holds only unlisted folders.
- Check: `npx vitest run src/extractors/filesystem/__tests__/project-folders.test.ts -t "another subroot"`.

### C-1.8.1-004 Fields directly in the object folder (S-1.8.1-004)

- Done: `*.field-meta.xml` placed in `objects/<Obj>/` (not `fields/`) are read with the `fields/` ones (packages/core/src/extractors/filesystem/index.ts, around lines 850-905); a same-named field in `fields/` wins. They are part of the object fingerprint (`directFields=`) only when present, so existing graphs keep their fingerprints.
- Check: `npx vitest run src/extractors/filesystem/__tests__/project-folders.test.ts -t "fields beside"` and `src/ingest/__tests__/project-folders-ingest.test.ts -t "directly in the object folder"` (node `CustomField:Acme_Order__c.Total__c` exists).

### C-1.8.1-005 Children-only standard objects (S-1.8.1-005)

- Done: an object folder with no `.object-meta.xml` is skipped only when it has no fields, direct fields, record types and validation rules (packages/core/src/extractors/filesystem/index.ts, around lines 862-880). Record types and validation rules were already part of the fingerprint; the stub's source URI is now the object folder when there is no `fields/` folder.
- Check: `npx vitest run src/extractors/filesystem/__tests__/project-folders.test.ts -t "children-only"`; `src/ingest/__tests__/project-folders-ingest.test.ts -t "Campaign"` (one RecordType and one ValidationRule node) and `-t "delta ingest notices"` (edit the record type, `runDeltaIngest` reports `changed: 1` without a rebuild and the node has the new label).

### C-1.8.1-006 Guest sharing rules (S-1.8.1-006)

- Done: `packages/core/src/parsers/rules/sharing-rule.yml` repeats the criteria-rule node and its edges (`SHARING_GRANTS`, `SHARING_TO_GROUP`, `SHARING_TO_ROLE`) over `sharingGuestRules` with `kind: "guest"`.
- Check: `npx vitest run src/ingest/__tests__/project-folders-ingest.test.ts -t "guest sharing"`.

### C-1.8.1-007 Missing Visualforce page (S-1.8.1-007)

- Done: two real causes found and fixed. (a) A page in a sibling subroot of the package directory (`force-app/<other>/default/pages/`) was never searched, see C-1.8.1-003. (b) Leaf files that are symlinks failed the `Dirent.isFile()` test and were dropped; `isFileEntry` (packages/core/src/extractors/filesystem/index.ts, around line 561) now follows a symlink to a file (never to a folder). Dotted names (`Name.With.Dots.page`) and pages under other `packageDirectories` already worked and now have tests. Not changed: a page in a sub-folder of `pages/` (sfdx does not allow it) and an upper-case suffix (`.PAGE`); neither was reproduced and the real cause for the reporter's page is unconfirmed, so a masked sample of their tree is still needed to be sure.
- Check: `npx vitest run src/extractors/filesystem/__tests__/project-folders.test.ts -t "Visualforce page shapes"`.
