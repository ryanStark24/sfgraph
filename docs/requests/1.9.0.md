# Request ledger: sfgraph 1.9.0

Every ask for 1.9.0 is logged here before it is built: the requester's exact words, acceptance criteria, the owning thread, and status. Every merged PR maps to an entry. Before publishing, a fresh, independent agent with no build context checks each entry against the built packages; any Fail blocks the release. Claims (what was done and how to check it) live in [../claims/1.9.0.md](../claims/1.9.0.md).

Source of the ask: the 2026-11-15 Code Analyzer spike for the Telltale app. A blind fixture of 15 planted defects (D01 to D15) was scanned by Salesforce Code Analyzer and by sfgraph 1.8.2; Code Analyzer caught D02 (async in loop), D08 (SOQL injection), D13 (LWC innerHTML) and D15 (Flow DML in loop) and sfgraph caught none of them (sfgraph caught only D04). Spike report: `code-analyzer-spike.md` in the owner's Telltale project files (not in this repo).

**Exact ask (the owner, Anshul, 2026-11-15 10:00Z):** decision card "How should Telltale get the checks Code Analyzer catches and sfgraph misses?" answered "Add the 4 checks to sfgraph".
**Scope given to the thread:** four static checks, each finding carrying file, line (or flow element name), rule id, severity and a short message, consistent with the existing finding shapes; output contracts additive only (Telltale parses them); synthetic test fixtures with positive and negative cases per rule; re-run on the blind project and report which of D01 to D15 are now caught and the noise count. No Salesforce org is contacted. No version bump, no publish (the maintainer's step).

Owner thread for every entry: "Research Salesforce MCP tools for Telltale" (project "Salesforce Live Debug").

Status values: Logged, Building, Built (PR open), Merged, Verified, Deferred.
